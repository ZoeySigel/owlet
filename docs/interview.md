# 面试与演示提纲

## 当前可用的简历描述

Owlet 图文创作平台（个人项目，React / TypeScript / Go / PostgreSQL）：实现邀请码账号、商品与品牌快照、四页模板编辑、自动保存及 PNG/ZIP 导出；设计 PostgreSQL 持久任务队列和 SSE 状态回放，通过事务预留、幂等键与唯一结算流水控制用户日额度和全站月额度；实现已发出调用的未知状态保留、图片下载恢复及历史版本清理，并用数据库与浏览器用例验证核心流程。

真实 BigModel 调用、云端上线及压测未完成前，不加入“已上线”“服务 X 用户”“QPS X”或真实费用节约比例。工具辅助完成代码后，应逐段理解关键模块再用于面试，不把未掌握的实现说成独立熟练掌握。

## 三分钟演示

1. 商品资料和品牌资料；创建项目，说明快照避免公共资料变化影响旧作品。
2. 手动编辑封面与三页内容，切模板、裁剪商品、导出 ZIP。
3. 启动模拟生成、刷新页面，解释后台任务与浏览器连接独立；确认后生成背景、局部重写、选旧版本。
4. 打开费用与管理后台，区分 reserved 和 spent；展示测试覆盖，说明真实 API 待验证。

## 必须能讲清的问题

- 为什么不用 Redis 队列？当前吞吐小、预算紧，PostgreSQL 已承载业务，队列与额度可在同一事务提交；代价是数据库负载与未来扩展边界。
- 重复点击为何不多扣？用户+幂等键唯一约束，输入校验，settled 行锁及账本主键共同作用。
- 为什么不能超时就重试？超时只说明本地没拿到响应，不能证明供应商没生成或没计费；未知状态保留额度，由管理员对账。
- 刷新为什么任务不停？任务先持久化，Worker 独立执行；SSE 是通知通道，状态可重新查询。
- 为什么金额用整数？避免浮点累计误差；1 元对应一百万微元，所有预留与结算在事务中更新。
- 为什么文本也串行？当前为 2GB 邀请演示降低复杂度，未来可拆文本工作池，但必须保持单用户限制、图片并发和一致性。
- 如何保证删除不误伤？当前资料、历史版本和任务结果均检查引用，清理与新增引用共享事务锁；代价是 JSON 扫描与保守保留。
- 当前最需要改进什么？真实模型契约验证、服务器恢复演练、版本化迁移、可信代理限流，以及资产显式引用表。

阅读顺序：main.go 身份与路由 → documents.go 保存与隔离 → jobs.go 额度事务 → provider.go 外部调用 → recovery.go 不确定性处理 → jobs_test.go 证据。
